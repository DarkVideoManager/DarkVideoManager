# 앱 업데이트

자동 업데이트가 포함된 버전의 **Windows 설치형 앱**에서 사용할 수 있습니다. 기존 0.3.3 이하에는 이 기능이 없으므로, 이 기능을 포함한 버전이 배포되면 공식 릴리스의 설치형 파일로 한 번 직접 설치해야 합니다. 기존 라이브러리와 설정은 같은 앱 데이터 위치를 사용합니다.

앱 시작 15초 뒤와 이후 6시간마다 공식 GitHub의 정식 릴리스를 확인합니다. 새 버전이 있으면 설치형 파일을 자동으로 다운로드하고 알림을 표시합니다. **재시작하여 업데이트**를 누르면 자막·영상 변환 대기열을 저장하고 작업·플레이어·데이터베이스 정리를 마친 뒤 설치 프로그램을 실행합니다. 설치 위치에 따라 Windows 권한 확인이나 설치 화면이 표시될 수 있습니다.

**나중에**를 누르면 알림만 숨깁니다. 설정 → 앱 업데이트에서 다시 적용할 수 있습니다. 일반적인 앱 종료만으로 설치하지 않으며 재생 중 강제로 재시작하지 않습니다. 작업 저장이나 종료 정리가 실패하면 설치를 진행하지 않습니다.

설정에서 **자동 확인 및 다운로드**를 끌 수 있습니다. 이 설정은 다음 실행에도 유지되며, 이미 시작한 다운로드에는 적용되지 않습니다. 끈 상태에서도 **새 버전 확인**, **업데이트 다운로드**를 직접 사용할 수 있습니다. 다운로드 실패나 파일 해시 불일치가 발생하면 설치 준비 상태로 넘어가지 않으며 다시 시도할 수 있습니다. 시험판과 이전 버전으로의 자동 전환은 하지 않습니다.

포터블은 자동으로 새 버전을 확인하고 공식 릴리스 다운로드를 안내합니다. 실행 중인 포터블 파일을 자체 교체하거나 설치형으로 바꾸지 않습니다. 개발 실행·압축을 푼 실행 폴더에서는 자동 확인·다운로드를 시작하지 않습니다. 브라우저 데모에는 설치 기능이 없습니다.

## 배포 시 필요한 파일

`electron-updater` 6.8.10과 `electron-builder` 26의 NSIS 업데이트 형식을 사용합니다. 공개 GitHub 저장소의 업데이트 주소는 패키지 안에 고정되며, 화면에서 임의의 서버·실행 파일 경로를 지정할 수 없습니다. 다운로드된 설치 파일의 SHA-512를 업데이트 정보와 대조합니다. Windows 코드 서명을 구성하면 업데이터의 기본 게시자 검증도 적용됩니다. 현재 unsigned 배포를 코드 서명된 배포로 표현하지 않습니다.

기존 릴리스 파일과 함께 다음 두 파일을 **같은 정식 릴리스**에 반드시 첨부합니다.

- `latest.yml`
- `DarkVideoManager-Setup-버전-x64.exe.blockmap`

`npm run build:win`은 업데이트 버전·설치 파일명·크기·SHA-512·blockmap·내부 공개 저장소 설정을 검사하고 두 업데이트 파일을 `release/candidate/`에 준비합니다. 기존 배포 후보 워크플로가 이 폴더에 실행 파일과 소스를 모으고 모든 파일을 SHA256SUMS.txt에 포함합니다. 새 버전을 준비할 때는 깨끗한 후보 폴더를 사용하세요. 초안에 모든 파일을 올리고 대조한 뒤 정식 릴리스를 공개하세요. 업데이트 정보만 먼저 공개하거나 기존 버전의 파일을 다른 내용으로 덮어쓰지 않습니다.

`node scripts/smoke-app-updates.cjs`는 별도 앱 프로필과 localhost 임시 서버에서 실제 업데이터의 다운로드·해시 확인·손상 파일 거부·다운그레이드 거부를 검사합니다. 선택적으로 검사할 배포 앱 EXE 경로를 인자로 넘길 수 있습니다. 검사 중 설치 프로그램을 실행하거나 현재 설치를 교체하지 않습니다. 실제 Windows 설치 교체·재시작 검증은 별도 테스트 설치에서 수행해야 합니다.
