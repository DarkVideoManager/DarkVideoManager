# AI 자막 생성

자막 생성은 영상의 음성을 인식해 SRT 파일로 저장하는 작업입니다. 영상을 재생하는 것만으로 시작하지 않으며, 재생과 동시에 제공되는 실시간 통역 기능은 아닙니다.

## 처음 자막 만들기

1. 처음 사용한다면 상단 **자막 생성 → 자막 환경 자동 설치**에서 준비 상태를 확인합니다. 필요한 구성 요소와 권한 요청은 아래 [자동 설치 안내](#앱에서-자동-설치)를 따릅니다.
2. 라이브러리에서 영상을 선택하고 **정보 → AI 자막 생성**을 엽니다. **음성 인식 모델**과 **영상 언어**를 고릅니다. 기본 모델은 `base`이며, `large-v2`도 이 목록에서 선택할 수 있습니다.
3. **한국어 번역 자막도 생성** 여부를 고릅니다. 기본으로 선택되어 있지만 Google 사용 설정과는 별개입니다. 상단 **자막 생성 → 한국어 번역 설정**에서 로컬 번역 준비 상태와 Google 사용 여부를 확인합니다.
4. **자막 생성 시작**을 누릅니다. 단계별 진행률과 완료·실패 상태는 영상의 패널이나 상단 **자막 생성** 대기열에서 확인합니다. 화면을 나갔다 돌아와도 작업은 유지됩니다.
5. 완료되면 영상과 같은 폴더의 `영상이름.ai.srt`(원어), 번역을 선택했다면 `영상이름.ai.ko.srt`(한국어)를 확인합니다. 플레이어의 **자막 선택**에서 결과를 고릅니다. 같은 이름이 있으면 번호를 붙여 보존합니다.

영상 폴더에 쓰기 권한이 필요하며, 제거된 영상과 읽기 전용 라이브러리에서는 생성할 수 없습니다. 번역만 실패한 경우에는 원어 자막을 유지하고 오류를 표시합니다. 이때 **재개 · 다시 시도**로 저장한 번역 다음부터 이어갈 수 있습니다.

모델 선택 아래의 안내와 **처음 자막 만들기 · 모델·언어·비용**을 화면에서 펼쳐 볼 수 있습니다. 개인정보와 공식 다운로드 링크는 앱 **설정**, 자막 생성 패널, 자막 환경·한국어 번역 설정의 **개인정보 처리 · 공식 배포 확인**에 있습니다.

라이브러리의 영상 카드에서도 자막 작업을 확인할 수 있습니다. 실행 중인 카드는 청록색 테두리와 함께 썸네일 아래에 현재 단계·진행률을 표시하며, 대기·일시정지·실패는 별도 문구로 구분합니다. 영상을 선택하지 않아도 자동 갱신되고, 완료되면 진행 표시가 사라지며 **자막 있음** 상태가 반영됩니다.

## 기존 자막 삭제 후 재생성

기존 외부 자막이 있으면 **기존 자막 삭제 후 재생성**을 누릅니다. 확인 화면에 표시된 파일을 확인하고 **삭제 후 재생성**을 선택하면 재생성 작업을 큐에 추가합니다. 다른 영상의 자막 생성이나 라이브러리 작업이 진행 중이어도 대기열에 추가할 수 있습니다. 실행 차례가 되면 해당 자막을 휴지통으로 옮긴 뒤, 선택한 모델·언어·한국어 번역 설정으로 처음부터 생성합니다. 이전 작업의 중간 결과는 재사용하지 않습니다.

대기 중에는 기존 자막 파일을 그대로 유지합니다. 실행 전에 큐에서 **일시정지**하거나 **삭제**해도 기존 자막은 삭제되지 않습니다. 일시정지한 재생성 작업은 **재개**한 뒤 실행 차례가 되면 기존 자막을 휴지통으로 옮깁니다.

영상 파일과 내장 자막은 유지합니다. 내장 자막만 있는 영상도 **자막 생성 시작**으로 새 외부 자막을 만들 수 있습니다. 일반 **자막 생성 시작**은 기존 자막을 보존합니다.

해당 영상의 대기·진행·일시정지 작업이 남아 있으면 먼저 자막 생성 큐에서 완료하거나 삭제해야 재생성할 수 있습니다. 실행 차례에 삭제 또는 생성이 실패하면 작업에 오류를 표시합니다. 이미 삭제된 자막은 휴지통에서 복원할 수 있으며, 생성 실패 후에는 **자막 생성 시작**으로 다시 시도할 수 있습니다.

## 대기열과 백그라운드 실행

상단 **자막 생성** 탭에서 모든 라이브러리의 작업을 관리합니다. 여러 영상에서 생성을 누르면 순서대로 대기열에 추가되며, 한 번에 하나씩 처리합니다.

- **일시정지**: 대기 작업은 실행을 보류하고, 진행 중인 작업은 완료된 음성 인식 구간과 번역 문장을 보관한 뒤 멈춥니다. 다른 대기 작업은 계속 처리합니다.
- **재개**: 저장된 구간부터 이어서 진행합니다. 멈추는 순간 처리 중이던 구간·문장은 다시 처리할 수 있으며, 음성 추출 도중 멈췄다면 추출 단계부터 시작합니다.
- **삭제**: 대기열 항목과 미완성 임시 파일만 지웁니다. 이미 저장된 SRT와 원본 영상은 그대로 유지합니다.
- **ESC / 창 닫기(X)**: 대기·진행·일시정지 작업이 남아 있으면 트레이로 숨겨지고 자막 생성은 계속됩니다. 플레이어의 ESC는 기존처럼 라이브러리로 돌아갑니다.
- **다시 열기**: 트레이 아이콘을 클릭하거나 프로그램을 다시 실행합니다. 트레이 메뉴의 **자막 생성 대기열**은 해당 탭을 바로 엽니다.
- **완전히 종료**: 트레이 메뉴에서 선택하면 미완료 작업을 일시정지하고 보관한 뒤 앱을 끝냅니다. 다음 실행에서는 **재개**를 눌러 이어갑니다.

대기열은 앱 데이터의 `subtitle-queue.json`, 중간 진행 내용은 `subtitle-jobs/queue-작업ID/`에 저장합니다.
대기열 파일 교체가 잠깐 차단되면 짧게 재시도합니다. 계속 저장할 수 없으면 기존 저장 파일과 진행 내용을 유지하고 미완료 작업 전체를 일시정지합니다. 화면에 표시된 저장 위치의 쓰기 권한과 다른 프로그램의 파일 사용 상태를 확인한 뒤 **저장 다시 시도**를 누르세요. 저장이 복구되면 선택한 미완료 작업만 재개하며, 다른 일시정지 작업은 각각 재개할 수 있습니다. 이미 자막이 완성된 작업의 저장 재시도는 음성 인식이나 자막 발행을 반복하지 않습니다.
일시정지한 작업의 원본 영상이 바뀌면 잘못된 자막을 이어 붙이지 않도록 재개를 거부합니다. 그 경우 작업을 삭제하고 다시 추가하세요.
진행 중인 라이브러리 작업과 겹치면 해당 라이브러리가 사용 가능해질 때까지 기다립니다.

## 실행 환경

새 자막 작업의 음성 인식은 Windows의 **whisper.cpp + Vulkan GPU**로 처리합니다. AMD Radeon을 포함한 Vulkan 지원 GPU와 최신 그래픽 드라이버가 필요합니다. GPU 초기화에 실패하면 원인을 표시하며, CPU로 자동 전환하지 않습니다.

작업의 **음성 인식** 항목은 엔진이 실제 Vulkan 사용을 확인한 뒤 `Vulkan GPU · Vulkan0 (엔진 확인)`처럼 표시합니다. 모델을 내려받거나 장치를 확인하기 전에는 **실제 처리 장치 확인 전**으로 표시하며, `Vulkan0`은 엔진의 장치 식별자이므로 GPU 제품명과 다를 수 있습니다. 재개한 작업의 저장된 확인 정보는 **이전 인식 기록**으로 구분합니다. 이전 CPU 작업은 기존 진행 내용을 유지하기 위해 CPU로 재개하며 화면에도 이를 표시합니다.

음성 추출과 음성 구간 감지(VAD)는 CPU를 사용할 수 있고, Vulkan 음성 인식 중에도 CPU 사용량이 올라갈 수 있습니다. 음성 인식 엔진의 후속 VAD 문맥에 나오는 `no GPU found` 로그만으로 음성 인식의 GPU 미사용을 판단할 수 없습니다. 한국어 번역은 Google Cloud 또는 로컬 Ollama의 별도 단계이며 실제 사용한 번역 경로를 작업에 표시합니다. Ollama의 GPU·CPU 선택은 Ollama에서 관리하므로 음성 인식의 Vulkan 사용 표시로 번역 장치까지 확인한 것은 아닙니다.

### AMD·NVIDIA 지원과 문제 구분

모델 선택 화면과 한국어 번역 설정의 **AMD·NVIDIA 지원 · 실제 처리 장치 확인**에서 같은 안내를 볼 수 있습니다. 안내를 펼치는 동작은 설치나 모델 다운로드를 시작하지 않습니다.

| 처리 단계           | 현재 구성                    | 확인할 조건                                                                                                                          |
| ------------------- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 새 작업의 음성 인식 | Windows whisper.cpp / Vulkan | AMD Radeon·NVIDIA GeForce의 Vulkan 지원 GPU와 제조사의 호환 드라이버, 선택 모델을 실행할 메모리. CUDA·ROCm 별도 설치는 필요하지 않음 |
| 로컬 한국어 번역    | WSL Ollama                   | 해당 Ollama 버전·GPU·드라이버의 지원 조건. 장치 선택은 Ollama가 관리하며 음성 인식의 Vulkan 표시와 별개                              |
| Google Cloud 번역   | 선택한 외부 서비스           | 계정·API·사용량 설정. 이 번역 경로를 선택해도 로컬 음성 인식의 GPU 조건은 유지됨                                                     |

현재 프로그램은 모든 Radeon·GeForce 제품의 실물 검증을 보장하지 않습니다. 제조사 이름만으로 지원을 확정하지 말고 드라이버, Vulkan 초기화 결과와 실제 작업의 **음성 인식** 항목을 확인하세요. 초기화가 실패한 새 음성 인식 작업은 CPU로 자동 대체하지 않습니다. 예전에 CPU로 시작한 작업의 재개는 저장된 처리 경로를 유지합니다.

Vulkan 초기화 오류는 GPU·드라이버를 확인하고, 메모리 부족 오류는 더 작은 모델로 짧은 입력을 확인합니다. 반면 `HCS_E_HYPERV_NOT_INSTALLED`, `0x80370102` 또는 가상 머신 시작 오류는 WSL 준비 문제입니다. Windows 가상 머신 플랫폼, BIOS/UEFI CPU 가상화, 하이퍼바이저 부팅 시작 설정을 확인하고, 가상 PC라면 호스트의 중첩 가상화 지원도 확인합니다. 이를 GPU 제조사 미지원이나 모델 오류로 단정하지 않습니다.

### 모델·언어·사양·비용

앱에서 선택할 수 있는 음성 인식 모델은 아래 6개입니다. 용량은 앱에 고정된 GPU 모델 파일의 다운로드 크기를 십진 MB/GB로 반올림한 값이며, 실행에 필요한 RAM·GPU 메모리와는 다릅니다.

| 모델       | GPU 모델 다운로드 | 선택 시 확인할 점                             |
| ---------- | ----------------- | --------------------------------------------- |
| `tiny`     | 약 78 MB          | 작은 모델로 설치·인식 동작 확인               |
| `base`     | 약 148 MB         | 앱 기본값, 먼저 짧은 영상으로 확인            |
| `small`    | 약 488 MB         | 큰 모델로 바꿀수록 저장 공간·메모리 사용 증가 |
| `medium`   | 약 1.53 GB        | GPU 메모리 여유 확인                          |
| `large-v2` | 약 3.09 GB        | 대형 모델, v3와 별도 파일 다운로드            |
| `large-v3` | 약 3.10 GB        | 대형 모델, v2보다 항상 정확하다는 보장 없음   |

모델이 없으면 처음 선택해 생성할 때 내려받습니다. 선택 변경은 이후 시작하는 작업에 적용되며, 이미 대기 중인 작업의 설정은 바꾸지 않습니다. 모델 파일은 [앱의 고정 목록](../resources/subtitles/gpu-models.json)에 기록된 크기와 SHA-256으로 확인합니다. GPU용 파일과 이전 CPU용 모델은 서로 다른 캐시를 사용합니다.

**영상 언어**는 자동 감지, 일본어, 영어, 한국어, 중국어를 직접 선택할 수 있습니다. 자동 감지에서는 인식 엔진이 지원하는 다른 언어도 감지할 수 있으나 앱에서 모든 언어의 정확도를 검증한 것은 아닙니다. 출력은 인식한 원어이며 선택적 번역의 대상은 한국어입니다. 별도의 외부 인식 엔진을 선택하거나 영어 전용 `.en` 모델을 지정하는 화면은 없습니다.

Windows 10/11 x64와 Vulkan 지원 GPU·최신 드라이버가 필요합니다. 처음에는 `base`로 짧은 영상을 처리해 보고 큰 모델을 선택하세요. 모델 파일 외에 실행용 메모리, 추출 음성·중간 결과 공간, 번역 모델 공간이 필요합니다. 앱 전체에 대해 검증한 최소 RAM·VRAM 수치나 GPU별 처리 시간표는 없습니다. 영상 길이·음질·GPU·언어·번역 방식에 따라 시간과 품질이 달라지며, 다른 플레이어의 자막 기능과 비교한 품질 우위를 약속하지 않습니다. 엔진 자체의 모델·메모리 참고치는 [whisper.cpp 공식 안내](https://github.com/ggml-org/whisper.cpp#memory-usage)를 참고하되 앱 전체의 요구량으로 해석하지 마세요.

| 단계                      | 현재 처리 방식                                                           | 준비·비용                                                        |
| ------------------------- | ------------------------------------------------------------------------ | ---------------------------------------------------------------- |
| 원어 인식                 | 새 작업은 Windows whisper.cpp/Vulkan, 이전 CPU 작업은 기존 엔진으로 재개 | GPU와 모델 필요. 로컬 처리에 외부 API 요금 없음                  |
| 로컬 한국어 번역          | WSL Ubuntu의 Ollama `qwen3:8b`                                           | 자동 설치로 모델 준비. 별도 번역 API 요금 없음                   |
| 선택적 온라인 한국어 번역 | Google Cloud Translation Basic NMT                                       | 기본 꺼짐. 본인의 결제 계정·API 키 필요. 사용량에 따른 요금 가능 |

앱 자체 이용료는 없습니다. 로컬 처리에도 PC 자원·전력·다운로드 비용은 들 수 있습니다. Google은 **사용을 켜고 API 키를 저장한 경우**에 사용하며, 키 없음·비활성화·앱 한도 부족·요청 오류 시 준비된 로컬 Ollama로 전환합니다. 한국어 번역을 선택하지 않으면 번역 요청을 보내지 않습니다. Google 요금과 앱 한도의 차이는 아래 [한국어 번역](#한국어-번역)을 확인하세요.

### 앱에서 자동 설치

상단 **자막 생성 → 자막 환경 자동 설치**에서 준비 상태를 확인한 뒤 설치 버튼을 누릅니다. 영상의 **AI 자막 생성** 화면에서도 설치 화면을 열 수 있습니다. 실행파일에 포함된 음성 인식 엔진을 확인하고, 기본 `base` 음성 모델과 음성 구간 감지 모델, WSL Ubuntu의 앱 전용 Python 환경, Ollama와 `qwen3:8b` 한국어 번역 모델을 준비합니다. 이미 사용할 수 있는 구성 요소와 번역 모델은 다시 설치하지 않습니다.

WSL이 없는 PC에서는 Windows 관리자 승인이나 재시작이 필요할 수 있습니다. 관리자 권한은 Windows의 WSL 구성 요소를 준비할 때 사용하며, Ubuntu 배포판은 앱을 실행한 Windows 사용자 계정에 설치합니다. 화면의 안내에 따라 재시작한 뒤 앱에서 설치를 다시 누르면 준비 상태를 확인하고 이어서 진행합니다. 그래픽 드라이버는 PC 제조사나 GPU 제조사의 안내에 따라 준비해야 합니다.

WSL·Ubuntu는 Microsoft가 제공하는 온라인 다운로드 경로(`--web-download`)로 설치합니다. Windows 설치 중에는 현재 단계와 경과 시간을 표시하며, 앱을 종료해도 별도 설치 도우미가 진행 중인 Windows 설치를 기다립니다. 앱을 다시 실행한 뒤 **자동 설치**를 누르면 기존 설치의 상태를 확인합니다. 45분 안에 끝나지 않아도 설치를 강제 종료하지 않으며, 다시 눌러도 같은 설치를 중복 실행하지 않습니다. 오래된 Windows에서 이 설치 옵션을 지원하지 않으면 Windows 업데이트 후 다시 시도하세요.

설치가 진행되지 않거나 다시 설치하라는 안내가 나타나면 다음 항목을 확인하세요.

| 화면의 상태                                   | 다음 조치                                                                                                                                                                                                                 |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 설치를 마쳤는데 다시 설치가 필요하다고 표시됨 | **환경 다시 확인**으로 설치 결과를 다시 검사합니다. 완료된 Windows 설치 기록만 남아 있는 경우에도 실제 실행 환경을 확인합니다.                                                                                            |
| Windows 자막 실행 환경 단계에서 실패함        | 표시된 오류 코드와 설치 도구의 응답을 확인합니다. 권한 승인 취소와 가상화 오류에는 해당 조치를 안내하며, 그 밖의 실패는 실제 진단 내용과 인터넷 연결·Windows 업데이트 확인 안내를 표시합니다.                             |
| Windows 재시작 필요                           | 작업을 저장하고 재시작한 뒤 **설치 이어서 진행**을 누릅니다. Windows가 재시작 필요를 확인한 경우에만 이 상태를 표시합니다.                                                                                                |
| 가상화 기능을 사용할 수 없음                  | Windows의 가상 머신 플랫폼과 BIOS/UEFI 가상화 설정을 확인합니다. `0x80370102`는 재시작만으로 해결되지 않을 수 있습니다. [Microsoft 문제 해결 안내](https://learn.microsoft.com/windows/wsl/troubleshooting)를 참고하세요. |
| 오랫동안 준비 중임                            | 현재 단계의 경과 시간과 새 안내가 없는 시간을 확인하고, Windows 권한 승인 창과 인터넷 연결을 확인합니다. 화면이 오래 갱신되지 않았다는 안내만으로 설치 실패를 판정하지 않습니다.                                          |
| 권한 승인 후에도 진행되지 않음                | 현재 단계와 오류 안내를 확인합니다. Windows 설치가 계속 실행 중이면 새 설치를 시작하지 않고 기존 설치의 상태를 확인합니다.                                                                                                |

WSL 실행 확인과 Python 도구 확인을 따로 수행하므로, Python이 없다는 이유로 Windows 재시작을 반복 요청하지 않습니다. 실패한 단계는 **확인 필요**, 아직 시작하지 않은 단계는 **확인 전**으로 구분합니다. Windows 설치가 끝난 뒤에도 실행에 실패하면 재시작을 반복 권하는 대신 해당 단계의 오류와 필요한 조치를 표시합니다.

처음 설치하는 순서는 다음과 같습니다. 설치 화면의 **설치 전 확인 · 권한 승인 · Ubuntu 초기 설정**에서도 같은 안내를 볼 수 있습니다.

1. 앱에서 **자막 환경 자동 설치**를 직접 누른 뒤 나타난 Windows 권한 요청인지 확인합니다. 조직에서 관리하는 PC나 승인 권한이 없는 계정은 관리자에게 문의합니다.
2. **Windows 재시작 필요**가 표시되면 작업을 저장하고 재부팅한 뒤 앱에서 **설치 이어서 진행**을 누릅니다. 준비 중·재시작 필요 표시는 설치 실패와 구분됩니다.
3. 보통 Ubuntu 계정은 앱이 자동으로 준비합니다. **최초 사용자 설정이 필요하다는 메시지가 계속 표시되는 경우에만** 시작 메뉴에서 이미 설치된 Ubuntu를 열고 Linux 사용자명과 암호를 만듭니다. 이는 Windows 로그인과 별개이며, 암호 입력 시 화면에 문자가 나타나지 않는 것은 정상입니다.
4. 앱으로 돌아와 **환경 다시 확인** 또는 **설치 다시 시도**를 누릅니다. 설치 진행 중에는 같은 설치를 중복 실행하지 마세요. Microsoft Store에서 다른 Ubuntu를 추가 설치하기 전에 현재 앱 화면의 배포판·단계·오류를 먼저 확인합니다.

Ubuntu 최초 실행 화면의 예시입니다. 버전에 따라 문구가 다를 수 있으며, 앱이 계정을 준비한 환경에서는 이 화면이 필요하지 않을 수 있습니다.

```text
Enter new UNIX username: 사용할 Linux 이름
New password: (입력한 문자는 화면에 표시되지 않음)
Retype new password: 같은 암호 다시 입력
```

Ubuntu 계정 생성과 암호 입력 방식은 [Microsoft의 WSL 초기 환경 안내](https://learn.microsoft.com/en-us/windows/wsl/setup/environment#set-up-your-linux-username-and-password)를 참고하세요. 이 앱의 자동 계정 준비 방식은 아래 설명처럼 일반적인 수동 WSL 설치와 차이가 있습니다.

Ubuntu의 기본 사용자가 아직 `root`인 경우에는 암호 로그인이 잠긴 앱 전용 계정 `dvm-subtitles`를 만들고 사용합니다. 이 계정의 홈은 `/var/lib/dark-video-manager/user`입니다. Ubuntu의 기본 사용자를 바꾸지는 않으며, 이후 Ubuntu의 최초 사용자 설정을 마쳐도 앱은 같은 전용 계정과 모델을 계속 사용합니다. 이미 일반 사용자 설정을 마친 Ubuntu에서는 기존 사용자 환경을 유지합니다.

처음에는 인터넷 연결과 **15 GB 이상의 여유 공간**을 권장합니다. Ollama 설치 파일은 약 1.4 GB, 번역 모델은 약 5.2 GB이며 Ubuntu와 Python 환경, 압축을 푸는 임시 공간도 사용합니다. 설치 단계와 다운로드 진행률을 화면에 표시합니다. 중단하거나 실패한 뒤 다시 설치할 수 있으며, Ollama가 이미 내려받은 번역 모델 조각은 재사용합니다. Windows 구성 요소나 Ubuntu 기본 패키지를 준비하는 동안에는 해당 단계가 끝날 때까지 기다립니다.

Windows 음성 모델 다운로드에는 앱에 포함된 공개 인증서 묶음을 사용해 새 PC의 인증서 저장소를 보완합니다. 서버 인증서와 모델의 무결성 검사는 유지하며, Windows 인증서 저장소를 변경하지 않습니다. `TLS_BUNDLE` 오류는 앱의 인증서 파일이 없거나 손상된 경우이므로 최신 실행파일을 다시 설치하세요. `TLS_CERTIFICATE` 오류가 계속되면 Windows 날짜·시간과 네트워크 보안 설정을 확인하세요.

앱 전용 Python은 WSL의 `~/.local/share/dark-video-manager/venv`, 새 Ollama는 같은 폴더 아래 `ollama/`, 새 번역 모델은 `ollama-models/`에 저장합니다. 기존 Ollama 서버가 실행 중이면 그대로 사용하고 모델은 그 서버가 사용하는 저장 위치에 준비합니다. 앱 전용 Ollama가 재부팅 등으로 꺼졌다면 다음 로컬 번역을 시작할 때 다시 실행합니다. 일반 자막 생성 중에 Ollama나 번역 모델을 새로 다운로드하지는 않습니다.

위 경로의 `~`는 자막 도구를 실행하는 Linux 사용자의 홈입니다. 앱 전용 계정을 쓰는 경우 Python의 전체 경로는 `/var/lib/dark-video-manager/user/.local/share/dark-video-manager/venv`입니다. 전용 계정을 사용할 배포판 목록은 Windows 앱 데이터의 `subtitle-environment.json`에 저장합니다. 앱 데이터를 백업·복구할 때 이 파일도 보관하세요. 파일을 삭제해도 Linux 계정·도구·모델은 삭제되지 않으며, Ubuntu의 기본 사용자가 바뀐 상태에서는 기존 전용 환경과의 연결이 끊어질 수 있습니다. 반대로 이 파일을 유지한 채 Ubuntu를 초기화하거나 다시 설치하면 자동 설치가 전용 계정을 다시 준비하지만, Ubuntu에서 지워진 도구·모델은 다시 내려받아야 합니다.

### 소스 개발용 설치

GPU 결과의 자막 본문에 소량의 깨진 문자 데이터가 있으면 해당 문자만 `�`로 표시하고 정상 문장과 시간은 보존합니다. 손상이 심하거나 언어·시간·결과 구조가 잘못된 경우에는 오류를 표시합니다. 실패한 작업의 **재개 · 다시 시도**를 누르면 마지막으로 저장한 구간 다음부터 처리합니다.

실행파일에는 Windows 음성 인식 런타임이 포함됩니다. 소스에서 실행하거나 실행파일을 빌드할 때는 프로젝트 폴더에서 한 번 설치합니다.

```powershell
npm run setup:subtitles:gpu
npm run setup:subtitles
```

`setup:subtitles:gpu`는 프로젝트의 `resources/subtitles/native`에 Windows GPU 런타임을 준비합니다.
한국어 번역과 이전 CPU 작업의 재개에는 WSL `Ubuntu-24.04`의 Python 3을 계속 사용합니다.
`setup:subtitles`는 WSL의 `~/.local/share/dark-video-manager/venv`에 전용 환경을 만들고
faster-whisper, 호환되는 PyAV, requests 및 CPU용 기본 `base` 모델을 설치합니다.
기존 `video_ai_manager` 파일이나 가상환경은 변경하지 않습니다. WSL 쪽 FFmpeg 설치는 필요하지 않습니다.
다른 배포판은 설치 시 `-Distribution`을 지정하고 앱 실행 전에 `DVM_WSL_DISTRO`를 같은 값으로 설정합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/setup-subtitles.ps1 -Distribution Ubuntu -Model small
$env:DVM_WSL_DISTRO = 'Ubuntu'
npm run dev
```

`tiny/base/small/medium/large-v2/large-v3`를 선택할 수 있습니다. 선택한 모델이 없으면 최초 생성 시 다운로드합니다.
GPU용 모델은 이전 CPU용 모델과 별개이므로 처음 사용할 때 추가 다운로드가 필요할 수 있습니다. 모델 준비가 끝난 뒤 원어 자막 생성은 오프라인으로 가능합니다. 큰 모델은 더 많은 GPU 메모리가 필요하며, GPU를 사용해도 인식 정확도가 자동으로 높아지는 것은 아닙니다.

이전 버전에서 음성 인식을 시작한 작업은 저장된 진행 내용과 자막 시간을 유지하기 위해 기존 CPU/int8 엔진으로 재개합니다. 이미 원어 인식이 끝난 작업은 음성을 다시 인식하지 않고 남은 한국어 번역만 이어갑니다. 기존 영상을 GPU로 처음부터 다시 인식하려면 기존 작업을 정리한 뒤 새로 생성하거나 **기존 자막 삭제 후 재생성**을 사용합니다.

## 한국어 번역

음성·영상 파일은 로컬에서 처리합니다. Google 사용은 기본으로 꺼져 있습니다. 사용을 켜고 API 키를 저장한 경우 온라인 번역에 **공식 Google Cloud Translation Basic의 NMT 모델**을 사용하며, 인식된 자막 텍스트를 Google에 전송합니다. 이전 버전의 Google 번역 웹페이지 접근 방식은 사용하지 않습니다.

상단 **자막 생성 → 한국어 번역 설정**에서 설정합니다.

1. Google Cloud 프로젝트에 결제 계정을 연결하고 Cloud Translation API를 활성화한 뒤 API 키를 발급합니다. 키의 API 제한을 Cloud Translation API로 지정하는 것을 권장합니다. [공식 설정 안내](https://cloud.google.com/translate/docs/setup)
2. 앱의 **Google Cloud API 키** 입력란에 키를 입력하고 **Google Cloud Translation 사용**을 켠 뒤 **번역 설정 저장**을 누릅니다. 키는 저장 후 화면에 다시 표시하지 않습니다. 입력란을 비워 저장하면 기존 키를 유지하며, **저장된 API 키 삭제**로 제거합니다.
3. **월 사용 한도**를 0~500,000자 안에서 설정합니다. 다른 앱이나 프로젝트에서 같은 결제 계정의 Translation을 사용한다면 **이번 달 다른 앱·프로젝트 사용량**에 입력해 남은 한도에서 차감합니다. 외부 사용량은 앱이 자동 조회하지 않습니다.

Google의 월 무료 범위는 NMT 번역의 처음 500,000자에 해당하는 $10 크레딧이며, Basic과 Advanced 사용량 및 같은 결제 계정의 프로젝트 사이에서 공유됩니다. 이 앱에서 표시하는 사용량은 앱이 기록한 값입니다. 앱의 한도 설정이 Google 계정 전체의 과금을 차단하지는 않으므로, 다른 사용량과 실제 결제 내역은 Google Cloud에서도 확인하세요. [공식 요금 안내](https://cloud.google.com/translate/pricing)

월별 사용량과 외부 사용량 차감은 미국 태평양 시간(`America/Los_Angeles`)의 매월 1일 0시에 새 달로 전환합니다. Google 요청 전에 문자 수를 차감하며, 오류나 시간 초과로 응답을 확인하지 못해도 과금 여부가 불확실하므로 차감한 수를 되돌리지 않습니다. 앱을 다시 실행하거나 API 키를 바꾸어도 이번 달 사용량은 유지합니다. [월별 요금 구간 초기화 기준](https://docs.cloud.google.com/billing/docs/how-to/pricing-table)

키가 없거나 사용을 끄거나, 다음 요청이 남은 월 한도를 넘거나, Google 연결 오류·요청 제한이 발생하면 같은 WSL에서 실행 중인 Ollama의 **이미 설치된 `qwen3:8b`** 모델로 번역합니다.
Ollama와 번역 모델은 **자막 환경 자동 설치**에서 준비할 수 있습니다. 일반 자막 생성 중에는 번역 모델을 다운로드하지 않습니다. 로컬 번역으로 전환하면 남은 자막도 로컬에서 처리합니다.
로컬 번역의 연결 오류·시간 초과·미완료 응답은 번역할 문장마다 최대 3회 시도합니다. 같은 글자·단어·짧은 구절(최대 40자)이 10회 이상 이어지는 원문은 재시도할 때 번역에 전달하는 반복만 3회로 줄입니다. 숫자가 포함되거나 기호·공백만으로 된 반복은 축약하지 않습니다. 원어 자막과 저장된 원문은 그대로 유지하며, 미완료 번역은 저장하지 않습니다.
쉼표로 구분된 정수가 8개 이상 이어지는 단순한 숫자 나열은 순서·개수·구분자를 그대로 보존하고, 앞뒤의 일반 문장만 Ollama로 번역합니다. 부호·소수점·단위가 붙어 의미를 분리하기 어려운 경우에는 기존 방식으로 번역합니다. 모델이 숫자를 끝없이 늘리는 현상을 피하면서 같은 자막의 시간과 내용을 유지합니다. 앞뒤 문장 중 하나라도 번역에 실패하면 해당 자막의 부분 번역을 저장하지 않습니다.
마지막 시도에서는 응답 형식을 번역문 하나가 담긴 JSON으로 제한해 불필요한 출력 반복을 줄입니다. 이때도 완료 여부와 번역 내용, 응답 형식을 모두 검사하며 잘린 응답은 저장하지 않습니다.
두 번역 경로가 모두 실패하면 원어 자막을 보관하고 번역 실패를 표시합니다.
자막 생성 큐에서 실패한 항목의 **재개 · 다시 시도**를 누르면 저장된 번역 다음 문장부터 이어갑니다. 기존 원어 자막과 완료된 번역을 지우고 재생성할 필요는 없습니다.
자동 인식과 번역 결과는 원음이나 문맥에 따라 부정확할 수 있습니다.

## 저장과 재생

- 영상 옆에 `영상이름.ai.srt`(원어)와 `영상이름.ai.ko.srt`(한국어)를 저장합니다.
- 파일이 이미 있으면 `.ai.2.srt` / `.ai.2.ko.srt`처럼 번호를 붙여 기존 파일을 보존합니다.
- 영상 폴더에 쓰기 권한이 필요합니다. 제거한 영상 및 읽기 전용 라이브러리는 생성할 수 없습니다.
- 플레이어는 최신 한국어 생성본을 우선 선택하며 **자막 선택**에서 원어로 바꿀 수 있습니다.
- 라이브러리 새로고침 후에도 생성 자막과 언어 정보가 유지됩니다.
- 취소·삭제 시 미완성 작업을 정리합니다. 일시정지·완전 종료 시에는 중간 진행 내용을 보관합니다. 완료 파일은 유지합니다.
- 자막 생성 중 해당 라이브러리의 가져오기·삭제 등 충돌하는 작업은 완료 또는 취소 후 가능합니다.
- 외부 플레이어에서 이미 재생 중이라면 새 자막을 읽으려면 영상을 다시 열어야 할 수 있습니다.

### 진행 정보 저장 오류 후 다시 시도

WSL에서 `checkpoint.json`을 갱신할 때 `[Errno 21] Is a directory` 오류가 발생하면, 저장 대상이 일반 파일인지 확인한 뒤 앱에 포함된 Windows Python으로 파일 교체를 다시 시도합니다. 진행 정보와 작업 중인 SRT는 새 내용을 임시 파일에 모두 기록한 후 교체하며, 기존 파일을 먼저 지우거나 직접 덮어쓰지 않습니다.

이 오류로 실패한 작업은 수정된 버전에서 **재개 · 다시 시도**를 누르면 마지막으로 저장한 구간부터 이어갑니다. 실제로 저장 경로에 폴더나 링크가 있거나 Windows 파일 교체도 실패하면 작업을 중단하고 기존 내용을 보존합니다. 이 경우 작업 폴더의 충돌 경로와 쓰기 권한을 확인하세요.

## 구현 및 검증

이전 로컬 영상 관리 프로젝트의 mono/16kHz 전처리와 Google 번역 흐름을 참고했습니다. 새 작업의 음성 인식은 Windows Vulkan 엔진을 사용하며, 이전 CPU 작업은 faster-whisper/VAD 경로를 유지합니다.
영상의 첫 오디오 트랙을 사용하며, 특정 콘텐츠의 어휘 힌트나 일본어 고정값은 적용하지 않았습니다.
원어와 한국어 SRT는 같은 타임코드를 유지합니다.

```powershell
npm run typecheck
npm test
py -3 -X utf8 -m unittest discover -s resources/subtitles -p "test_atomic_output.py"
npm run test:e2e -- e2e/subtitles.spec.ts e2e/subtitle-queue.spec.ts e2e/subtitle-regenerate.spec.ts e2e/library-subtitle-progress.spec.ts
```

전체 Python 자막 테스트는 Linux/WSL에서 프로젝트 폴더로 이동한 뒤 `python3 -m unittest discover -s resources/subtitles -p "test_*.py"`로 실행합니다. 번역 시간 제한 테스트는 Linux 신호를 사용합니다.

실제 음성 영상으로 전체 파이프라인을 확인하는 선택적 통합 테스트도 있습니다.
해당 영상은 임시 폴더로 복사되며 원본을 수정하지 않습니다. 한국어 번역 요청에 자막 텍스트가 사용됩니다.

```powershell
$env:DVM_SUBTITLE_SMOKE_INPUT = 'C:\fixtures\speech.mp4'
npm test -- electron/main/services/SubtitleGeneration.integration.test.ts
Remove-Item Env:DVM_SUBTITLE_SMOKE_INPUT
```

실제 Electron 앱의 ESC 백그라운드 유지, 대기열 조작, 완전 종료 후 복원도 확인할 수 있습니다.
아래 검증은 별도 임시 앱 데이터와 복사한 영상을 사용합니다. 패키지를 검증하려면 마지막 인수로 압축 해제된 실행파일 경로를 지정합니다.

```powershell
npm run build
$env:DVM_SUBTITLE_SMOKE_FIXTURE = 'C:\fixtures\speech.mp4'
node scripts/smoke-subtitle-queue.cjs
node scripts/smoke-subtitle-queue.cjs 'dist-electron\subtitle-queue\win-unpacked\DarkVideoManager.exe'
node scripts/smoke-subtitle-regenerate.cjs 'dist-electron\subtitle-queued-regenerate\win-unpacked\DarkVideoManager.exe'
node scripts/smoke-library-subtitle-progress.cjs 'dist-electron\subtitle-library-progress\win-unpacked\DarkVideoManager.exe'
node scripts/smoke-subtitle-gpu.cjs 'dist-electron\subtitle-gpu\win-unpacked\DarkVideoManager.exe'
node scripts/smoke-subtitle-cloud.cjs 'dist-electron\subtitle-cloud-translation\win-unpacked\DarkVideoManager.exe'
Remove-Item Env:DVM_SUBTITLE_SMOKE_FIXTURE
```

재생성 검증은 임시 폴더에 만든 테스트 자막만 휴지통으로 옮기고, 같은 영상의 원어·한국어 자막이 새로 생성되는지 확인합니다.
GPU 검증은 새 작업의 Vulkan 체크포인트, 실제 GPU 처리 메시지, 원어·한국어 SRT 생성, 큐의 일시정지·재개와 앱 종료 후 복원을 확인합니다.
Cloud Translation 검증은 공식 API 요청을 가짜 응답으로 대체하며 실제 Google 요청이나 과금은 발생하지 않습니다. 실제 GPU 음성 인식 후 첫 번역 요청의 사용량이 먼저 기록되는지, 한도 도달 시 나머지 문장을 로컬 Ollama로 번역하는지, 재실행 후 사용량·암호화한 키가 유지되는지 확인합니다.
