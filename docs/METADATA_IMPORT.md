# Stash에서 영상 정보 가져오기

영상의 **상세 정보 → 정보 → Stash에서 정보 가져오기**에서 사용자가 관리하는 Stash 서버의 정보를 조회할 수 있습니다. 연결은 기본으로 꺼져 있고, 앱 시작·라이브러리 스캔·화면 열기만으로 조회하지 않습니다.

## 먼저 준비할 것

Stash는 별도로 실행하는 영상·메타데이터 관리 프로그램이며 DarkVideoManager에 포함되어 있지 않습니다. 본인 PC 또는 접속 권한이 있는 다른 서버에서 Stash를 실행하고, 그 서버에 영상 항목과 제목·설명·태그 등 조회할 정보를 먼저 등록해야 합니다. 빈 서버에 연결하면 후보가 나오지 않습니다. Stash에 있는 메타데이터를 참고해 이 앱의 로컬 영상을 분류하는 기능이므로 영상 파일을 Stash에서 내려받거나 업로드하지 않습니다.

앱의 **Stash에서 정보 가져오기** 창 위쪽에 있는 **처음 사용하시나요? Stash 준비와 적용 방법**을 펼치면 같은 준비·적용 안내를 볼 수 있습니다.

## 조회와 적용

1. **Stash 서버 주소**에 HTTPS 주소 또는 로컬 HTTP 주소를 입력합니다. 예: `http://localhost:9999`. `/graphql`은 자동으로 붙이며, 이미 붙은 주소나 하위 경로도 사용할 수 있습니다. LAN 서버는 HTTPS가 필요합니다.
2. 인증이 필요하면 Stash의 **Settings → Security → Authentication**에서 발급한 API 키를 입력합니다. **Stash 연결 사용**을 켜고 **연결 설정 저장**을 누릅니다. 키는 암호화하여 PC에 저장하며 저장된 값을 화면에 다시 표시하지 않습니다. 서버 주소를 바꾸면 기존 키를 제거하므로 필요하면 새 키를 입력합니다.
3. **조회할 파일명 또는 식별자**를 확인·수정하고 **조회 방식**을 고릅니다. **파일명·제목 검색**의 초기 검색어는 확장자를 제외한 파일명입니다. Stash의 `code` 필드에 저장된 작품 코드를 찾으려면 **작품 코드 (정확히 일치)**를 선택합니다. **Stash에서 후보 조회**를 누르면 이 검색어와 인증 정보가 지정한 서버에 전송됩니다.
4. 최대 20개 후보에서 작품 코드·날짜·스튜디오·제목을 비교하여 하나를 선택합니다. 텍스트 모드는 Stash의 파일 경로·제목·설명 등 텍스트 검색이며 작품 코드 필드를 포함하지 않습니다. 코드 모드는 `code` 필드의 정확한 일치를 조회합니다. 식별자가 같거나 파일명이 비슷해도 자동으로 같은 영상이라고 확정하지 않습니다. 결과가 많으면 검색어를 좁혀주세요.
5. 가져올 값을 수정하고 **제목 적용**, **설명을 메모에 적용**, **태그 적용** 중 필요한 항목만 체크합니다. 기존 값이 함께 표시되며 처음에는 모두 체크 해제되어 있습니다. **선택한 항목 적용**을 눌러 저장합니다.

태그 초안에는 기존 태그와 Stash 태그를 합쳐 넣습니다. **인물 이름을 태그에 추가**는 인물 이름도 추가하며, 중복된 이름은 대소문자를 구분하지 않고 정리합니다. 태그를 직접 편집해 장르 등 분류명을 추가할 수도 있습니다. 태그는 쉼표로 구분하며 이름 안의 쉼표도 구분자로 처리합니다.

미리보기 이후 선택한 항목이 다른 곳에서 바뀌면 전체 적용을 중단합니다. 닫고 다시 열어 현재 값을 확인하세요. 적용은 하나의 DB 트랜잭션으로 처리하므로 실패 시 일부 필드만 저장하지 않습니다. 적용 직후 **방금 적용 되돌리기**로 선택한 항목의 이전 값을 복원할 수 있습니다. 되돌릴 값이 다시 수정되었다면 덮어쓰지 않고 중단합니다. 되돌리기 버튼은 이 창에서 마지막으로 성공한 적용에만 제공하며 창을 닫으면 사라집니다.

## 문제가 생겼을 때

- **연결 실패:** 브라우저에서 Stash 자체가 열리는지, 서버가 실행 중인지, 최종 주소와 네트워크 연결이 맞는지 확인합니다. 다른 PC의 HTTP 주소는 허용하지 않으므로 HTTPS를 설정해야 합니다.
- **인증 실패:** Stash에서 API 키를 확인·발급한 뒤 이 창에서 연결 설정을 다시 저장합니다. 주소를 바꿨다면 기존 키가 삭제되므로 새 주소의 키를 다시 입력합니다.
- **후보 없음:** Stash에 해당 항목이 등록되어 있는지 확인합니다. 불필요한 파일명 문구를 줄이거나 제목으로 검색하고, 작품 식별자는 정확한 `code` 값으로 코드 조회를 사용합니다.
- **잘못된 후보:** 적용하기 전에는 다른 후보를 고르거나 검색어를 바꾸면 됩니다. 적용 직후에는 창을 닫기 전에 **방금 적용 되돌리기**를 사용합니다. 창을 닫은 후에는 이 창을 다시 열어 후보를 고르고 적용할 값을 수정합니다. 메모·태그는 상세 정보에서도 수정할 수 있습니다.
- **적용 충돌:** 미리보기 뒤 로컬 정보가 달라진 경우입니다. 창을 닫고 다시 열어 현재 값과 후보를 비교합니다. 실패한 적용은 기존 정보를 변경하지 않습니다.

## 지원 범위

- **정보 출처:** 사용자가 지정한 Stash 인스턴스의 공식 GraphQL 읽기 API. Stash-box, 웹사이트 스크래퍼, 자동 일괄 수집은 지원하지 않습니다.
- **저장:** 제목 → 제목, 설명 → 메모, 태그·선택한 인물 이름 → 태그. 인물·장르 전용 필드는 없어 태그로 분류합니다. 이 가져오기는 기존 카테고리·파일명·파일 내용·별점·재생 기록·하이라이트를 바꾸지 않습니다.
- **확인용 정보:** 코드·날짜·스튜디오는 후보를 구분할 때 표시하고 저장하지 않습니다. 카테고리 가져오기는 지원하지 않습니다.
- **표지:** 외부 표지·썸네일을 가져오지 않으며 기존 썸네일을 유지합니다.
- **실패:** 15초 초과, 1 MiB 초과 응답, 인증 실패, 호환되지 않는 API 응답을 표시하고 기존 메타데이터를 유지합니다. 다른 서버로의 리다이렉트를 따르지 않으므로 실제 서버의 최종 주소를 입력해야 합니다. 인증서 검증을 끄지 않습니다.

[Stash 공식 API 안내](https://docs.stashapp.cc/api/)와 [공식 GraphQL 스키마](https://github.com/stashapp/stash/tree/develop/graphql/schema)를 기준으로 `findScenes`를 사용합니다. 텍스트 모드는 `filter.q`, 코드 모드는 `scene_filter.code`의 `EQUALS` 조건을 사용하며 모두 `page: 1, per_page: 20`으로 제한합니다. [공식 검색 구현](https://github.com/stashapp/stash/blob/develop/pkg/sqlite/scene.go)에서 두 방식의 검색 범위를 확인했습니다. 로컬 테스트는 격리된 응답과 HTTP 서버로 검증하며, 실제 사용자의 Stash 인스턴스에 연결한 검증은 별도 설정이 필요합니다. 전송·보관·삭제 내용은 [개인정보와 네트워크 사용](PRIVACY.md)에 설명되어 있습니다.
