# 플랫폼·네트워크 재생·영상 후처리 지원 범위

확인일: **2026-10-15**. 이 문서는 현재 저장소와 공식 기술 문서를 대조한 도입 검토입니다. [#24](https://github.com/DarkVideoManager/DarkVideoManager/issues/24)~[#27](https://github.com/DarkVideoManager/DarkVideoManager/issues/27)은 **검토 범위를 문서화한 상태이며 기능 구현 완료가 아닙니다.** 출시 일정이나 지원 기기 확약을 뜻하지 않습니다.

| ------------------------------------- | ---------------------------------------------------- | ----------------------------------------------------------- |
| #24 스트리밍 주소·한손 조작·자막 번역 | 등록한 로컬 파일 재생, 파일 기반 자막 생성           | 권한 있는 HTTPS 직접 미디어의 주문형 재생부터 분리 검토     |

| #26 macOS·Windows ARM                 | 배포 설정은 Windows x64 설치형·포터블                | macOS 이식과 Windows ARM 실기기 호환성 검사를 별도 진행     |
| #27 NVIDIA VSR·SVP4                   | 하드웨어 디코딩 지원과 외부 플레이어 실행            | 외부 플레이어에서 기능별로 먼저 검증, 앱 연동은 그 다음     |

## #24 스트리밍 URL과 자막·번역

현재 라이브러리 등록과 자막 파이프라인은 로컬 파일 경로를 기준으로 동작합니다. 웹페이지 주소나 스트리밍 URL을 입력하는 기능, 사이트 로그인·쿠키를 가져오는 기능, 라이브 음성을 실시간으로 인식·번역하는 기능은 없습니다. mpv 자체가 URL을 재생할 수 있다는 사실이 이 앱의 URL 입력·자막 처리를 지원한다는 뜻은 아닙니다.

현재 사용할 수 있는 방법은 **사용자가 내려받을 권한이 있는 영상을 파일로 준비한 뒤** 라이브러리에 등록하고 기존 재생·[자막 생성](subtitles.md) 기능을 이용하는 것입니다. 앱이 사이트에서 다운로드하거나 권한을 확인해 주지는 않습니다. 사이트의 재생 가능 여부와 다운로드·보관 허용 여부는 구분해야 합니다.

도입한다면 다음 순서로 검토합니다.

1. 로그인·DRM 없는 **HTTPS 직접 미디어 파일의 주문형(VOD) 재생**을 최소 범위로 정합니다. 일반 웹페이지 주소, 사이트별 추출기, 라이브 스트리밍은 이 범위에 넣지 않습니다.
2. 재생·탐색을 위한 길이 정보, Range 요청, 리다이렉트, 만료 URL, 연결 중단, 자막 위치와 캐시 공간을 검증합니다. URL의 비밀번호·토큰을 목록·로그에 노출하지 않고, 내부 주소 접근과 리다이렉트 정책도 별도로 설계합니다.
3. 파일로 완전히 확보한 VOD에서 현재의 음성 추출·체크포인트·SRT 저장 흐름을 재사용할 수 있는지 확인합니다. 원격 주소 재생만 성공한 것을 자막 생성 지원으로 판단하지 않습니다.
4. HLS/DASH는 별도 단계로 다룹니다. VOD의 고정 시간축과 라이브의 계속 갱신되는 구간·지연·재연결은 요구사항이 다릅니다. 라이브 자막은 증분 인식·동기화 설계가 먼저 필요합니다. DRM·사이트 인증 우회는 검토 범위에 포함하지 않습니다.
5. 한손 조작은 앱 플레이어의 기존 단축키를 재사용할 수 있는지 테스트하되, 외부 플레이어와 모바일 터치 조작은 별도로 검증합니다.

이 순서는 설계 제안입니다. HLS가 재생목록과 미디어 구간을 사용하는 구조 및 VOD·라이브 차이는 [RFC 8216](https://www.rfc-editor.org/rfc/rfc8216)에 정의되어 있습니다. Android 플레이어 후보의 컨테이너·코덱·HLS/DASH 지원 조건도 서로 다르므로 [Media3 지원 형식](https://developer.android.com/media/media3/exoplayer/supported-formats)을 앱 전체 지원표로 그대로 옮기지 않습니다.

## #25 모바일·Android·NAS

현재 앱은 PC 전용이며, 모바일에 APK를 설치하거나 PC 라이브러리를 자동 동기화하는 기능은 없습니다. NAS 전용 계정 연결, FTP·FTPS·SFTP 주소 입력, 원격 자막 생성 API도 없습니다. Windows가 NAS 공유를 접근 가능한 폴더로 제공하는 경우는 전용 NAS 연동과 구분해야 하며, 해당 공유의 권한·연결 복구·자막 쓰기는 별도 확인이 필요합니다.

현재의 수동 대안은 PC에서 원어·한국어 SRT를 만든 뒤 **영상과 원하는 SRT를 사용자가 휴대전화로 함께 이동**하고, 외부 모바일 플레이어에서 자막 파일을 직접 선택하는 것입니다. 파일명 자동 인식·인코딩·코덱 지원은 외부 플레이어에 따라 다릅니다. 앱이 전송이나 모바일 재생 성공을 보장하지 않으며 휴대전화에서 같은 AI 모델을 실행하지도 않습니다.

우선 검토안은 모델을 PC에 두고 모바일에서는 재생·자막 선택을 담당하는 **같은 LAN의 동반 앱**입니다. 구현 전에 사용자 승인 페어링, 인증, 연결 암호화, 접근 가능한 라이브러리 범위, PC 절전·연결 끊김, 읽기 전용 권한, 자막 동기화와 휴대전화 코덱을 검증해야 합니다. 서버를 만들더라도 기본으로 공인 인터넷에 노출하거나 공유기 포트·방화벽을 자동 개방하는 방식은 제안하지 않습니다.

NAS 직접 연결은 별도 후속 범위입니다. FTP, TLS를 사용하는 FTPS, SSH 기반 SFTP를 같은 프로토콜로 취급하지 않습니다. 특히 일반 FTP의 인증 정보를 암호화된 연결이라고 표시해서는 안 됩니다. FTPS의 전송 보호는 [RFC 4217](https://www.rfc-editor.org/rfc/rfc4217)을 기준으로 검토하며, 비밀번호 저장·인증서 오류·디렉터리 접근 범위·대용량 탐색·중단 복구를 포함해야 합니다. Android의 자막·디코더 지원은 기기별 검증이 필요합니다.

## #26 macOS와 Windows ARM

현재 [배포 설정](../electron-builder.yml)은 Windows의 NSIS·포터블 **x64**만 정의합니다. 미디어 리소스도 `win32-x64`이고, 자막 준비는 Windows 실행파일·PowerShell·WSL Ubuntu를 사용합니다. Electron이 여러 OS를 지원하는 것만으로 이 앱의 다른 OS 배포본이 생기지는 않습니다.

| 대상                        | 현재 판정                                   | 지원 전 필요한 확인                                                          |
| --------------------------- | ------------------------------------------- | ---------------------------------------------------------------------------- |
| Windows x64                 | 현재 배포 대상                              | Windows 버전·GPU 드라이버·선택적 AI 환경의 조건은 기존 안내 적용             |
| macOS Intel / Apple Silicon | 배포본·자동 설치 경로 없음                  | 아키텍처별 네이티브 의존성, 번들·서명·권한·자막 실행 경로 구현과 실기기 검사 |
| Windows ARM64               | ARM64 배포본 없음, x64 배포본 호환성 미검증 | 에뮬레이션에서 설치·DB·FFmpeg·재생·자막을 각각 검사                          |
| Linux 데스크톱              | 배포 대상 아님                              | WSL 내부 도구 사용 가능 여부와 Linux GUI 앱 지원은 별개                      |

macOS 도입 시에는 다음 작업이 필요합니다.

- `better-sqlite3`, FFmpeg·FFprobe, 음성 인식 런타임을 대상 CPU에 맞게 빌드·번들링하고 라이선스·소스 고지를 준비합니다.
- Windows Vulkan 음성 인식과 WSL Python·Ollama 설치를 macOS 네이티브 방식으로 대체하고, 사용할 GPU 백엔드·모델·취소·재개 동작을 검증합니다.
- Windows 경로·휴지통·탐색기·외부 플레이어 호출·트레이·키 저장을 해당 OS 동작으로 확인하고, 사용자 데이터 이전 및 파일 접근 권한을 시험합니다.
- macOS에서 앱 서명·공증·설치·업데이트와 Intel/Apple Silicon별 실행을 확인합니다. 네이티브 의존성과 서명은 [electron-builder 26의 다중 플랫폼 안내](https://www.electron.build/v26/docs/features/multi-platform-build/)에 따른 별도 준비가 필요합니다.

Microsoft는 [Windows 11 on Arm에서 x86·x64 에뮬레이션](https://learn.microsoft.com/en-us/windows/arm/apps-on-arm-x86-emulation)을 제공한다고 설명합니다. **이는 DarkVideoManager 전체 기능의 호환성 보증이 아닙니다.** Windows 10 on Arm의 에뮬레이션 범위도 같지 않습니다. x64 앱 실행 여부, GPU 드라이버·Vulkan 사용, WSL 배포판과 설치 바이너리 아키텍처는 각각 확인해야 하며, 실제 ARM 장비의 설치·실행 성공 또는 실패를 이번 검토에서 측정하지 않았습니다.

## #27 NVIDIA VSR와 SVP4

두 기능의 목적이 다릅니다.

| 기능                                   | 목적                                                         | 현재 앱에서의 상태                                       |
| -------------------------------------- | ------------------------------------------------------------ | -------------------------------------------------------- |
| NVIDIA RTX Video Super Resolution(VSR) | 압축 흔적 감소·영상 해상도 확대                              | 전용 활성화·지원 판정·상태 표시 없음                     |
| SVP4 프레임 보간                       | 기존 프레임 사이에 새 프레임을 만들어 움직임을 부드럽게 처리 | SVP 설치·필터·연동 설정 없음                             |
| 하드웨어 디코딩                        | 압축 영상을 GPU 등의 디코더로 해제                           | 앱/외부 플레이어의 디코딩 기능이며 VSR·SVP 활성화와 별개 |

앱은 외부 mpv에 `--hwdec=auto-safe`를 전달합니다. 이는 [mpv 하드웨어 디코딩 옵션](https://mpv.io/manual/stable/#options-hwdec)이며 업스케일링이나 프레임 보간을 켜는 명령이 아닙니다. 앱이 Chromium/Electron을 사용하거나 설정에서 GPU 가속을 확인한 것만으로 VSR 적용을 판정하지 않습니다.

우선 경로는 **기능을 지원하도록 사용자가 구성한 외부 플레이어를 먼저 단독 검증한 뒤**, 앱 **설정 → 외부 플레이어**에서 해당 실행파일을 선택해 같은 영상으로 확인하는 것입니다. SVP의 mpv 연동은 [SVP 공식 mpv 안내](https://www.svp-team.com/wiki/SVP:mpv)에 따라 해당 빌드의 VapourSynth 지원 등 조건을 확인해야 합니다. 앱이 전달하는 디코딩 옵션이나 관리 스크립트가 외부 설정과 충돌하는지도 검증해야 하므로, 기존 mpv 설정이 있다는 이유만으로 앱 연동 성공을 약속하지 않습니다.

VSR는 [NVIDIA 공식 RTX Video FAQ](https://nvidia.custhelp.com/app/answers/detail/a_id/5448/~/rtx-video-faq)의 지원 GPU·드라이버·플레이어 조건을 확인합니다. NVIDIA가 안내하는 대응 플레이어에서 먼저 동작 여부를 확인하고, 앱 내 플레이어나 일반 mpv에서 자동 적용된다고 가정하지 않습니다. SVP의 목적과 프레임 생성 방식은 [SVP 공식 소개](https://www.svp-team.com/wiki/Main_Page)에 설명되어 있습니다.

향후 연동 판단에는 동일 영상의 활성 상태 표시, 프레임률·드롭·지연, 탐색·일시정지·자막 동기화, GPU 사용량과 AI 자막 동시 실행, 설정 원복을 포함해야 합니다. 이번 변경은 GPU 드라이버·NVIDIA 설정·mpv 설정 파일·SVP 구성을 자동으로 변경하지 않습니다. 실제 RTX 기기나 SVP4 설치 환경에서의 호환성 검사는 수행하지 않았습니다.

## 이번 검토의 완료 기준

현재 지원 범위, 수동 대안, 도입 순서와 검증 조건을 코드 및 위 공식 문서와 대조했습니다. URL 입력, 모바일 서버·앱, macOS/ARM 배포, VSR·SVP 직접 연동은 구현하거나 실기기에서 검증하지 않았습니다. 후속 구현은 각 이슈에서 지원 대상을 좁히고 재현 가능한 시험 환경을 정한 뒤 별도로 진행합니다.
