## 자동 검사 실패 조사

- #55의 기존 자막 필터 화면 검사는 첫 클릭으로 상세 패널과 가상 그리드가 바뀌는 도중 더블클릭하는 경합이었습니다. 상세 패널 표시를 먼저 기다리도록 고치고 같은 검사를 5회 연속 통과했습니다.
- #59의 기존 재생 화면 검사는 `page.goto` 직후 앱 API를 읽는 초기화 경합이었습니다. 테스트 준비 단계에서 API가 준비될 때까지 기다리도록 보완했습니다. 제품 코드나 제한 시간을 변경해 실패를 숨기지 않았습니다.
- 개별 PR에서 관찰한 기존 자막 자식 프로세스의 시간 초과는 같은 제한의 집중 재검증과 통합 검사로 구분했습니다. 개별 실행 결과를 전부 성공한 것으로 합산하지 않습니다.

## 통합과 배포 검증

가져오기 구문, 모델/GPU 안내의 검사 범위, 브라우저 데모의 공유 API 구현과 검증 배열이 함께 병합되는지 확인했습니다. 새 배포 버전은 package.json과 package-lock.json의 루트 버전을 일치시킵니다. 설치형·포터블·같은 버전의 앱 소스·미디어 대응 소스와 해시를 함께 배포합니다.

전체 단위·화면 검사, 배포 도구 검사, 패키지 실행·구성 비교의 최종 수치와 SHA-256은 같은 릴리스의 `VERIFICATION.md`와 `SHA256SUMS.txt`에 기록합니다. GitHub 검사 결과는 해당 커밋의 Actions에서 확인할 수 있습니다.

개발 의존성을 연결한 초기 패키지에서 필수 하위 모듈 누락을 발견해 해당 후보를 폐기했습니다. 배포용 의존성을 저장소의 `npm run setup`으로 독립 설치하고 네이티브 런타임을 확인한 뒤 다시 제작했습니다. 최종 파일은 배포본 실행과 새 기능의 실제 preload·IPC 경로까지 검증합니다.

작업 PC의 전체 로컬 참조를 포함한 기록 검사는 오래된 로컬 Stash 테스트 자료 7건을 탐지합니다. 해당 자료가 공개 main과 9개 PR의 기록에서 도달하지 않음을 별도로 확인했습니다. 릴리스 소스와 공개 기록은 분리된 깨끗한 복제본에서도 검사하며, 기존 로컬 기록을 삭제하거나 검사기를 우회하지 않습니다.

실제 새 Windows의 설치·제거·WSL 최초 설치와 재부팅, 모든 GPU·드라이버·코덱·언어, 실제 Stash 서버와 온라인 번역 품질은 이번 검토만으로 확인되지 않습니다. 코드 서명이 없는 실행 파일을 오탐 해소가 확인된 파일로 표현하지 않습니다.
